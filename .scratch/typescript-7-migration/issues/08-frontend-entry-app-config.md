**How `App.tsx`'s types reconcile with `types.ts`:** `App.tsx` imports `Todo`, `Category`, `ScratchNote` directly from `./types` for all its `useState` slices (`categories: Category[]`, `todos: Todo[]`, `scratchNotes: ScratchNote[]`, `selectedTodo`/`draftTodo: Todo | null`, `editingCategory: Category | null`, `searchResults: Todo[] | null`) — exactly the reuse Issue 07 flagged as expected. The loose-required-fields design (`Todo.title` only, `Category.name`/`color` only) paid off immediately: `handleOpenFullTodo`'s `setDraftTodo({ title })` — the in-memory pre-save draft — type-checks against `Todo` with no cast, which is the whole reason that type was shaped that way.

Beyond `types.ts` itself, `App.tsx` also imports types exported by the components it wires together, since those are the actual shapes its handlers need to match:
- `TodoSavePatch` (from `TodoDetail.tsx`) for `handleUpdateTodo`/`handleCreateTodoDetailed`'s `patch` parameter, and `Partial<TodoSavePatch>` for the shared `patchTodo` helper — this one type covers all three real call shapes that flow through it (a full `TodoSavePatch` from `handleUpdateTodo`, a `{ body }`-only patch from `handleSaveLinkedTodoField`, and a `{ linkedTodoIds }`-only patch when `patchTodo` itself is passed directly as `TodoDetail`'s `onReorderLinkedTodos` prop). Contravariance makes the last case work without any cast: a function accepting the wider `Partial<TodoSavePatch>` is assignable wherever the narrower `{ linkedTodoIds: string[] }` is expected.
- `CategoryFormValues` (from `CategoryForm.tsx`) for `handleCreate`/`handleRename`.
- `DraftScratchLine` (from `Scratchpad.tsx`) for `handleCreateScratchNote`, and `PromoteOptions` (from `ScratchNoteCard.tsx`, re-exported through `Scratchpad`'s prop) for `handlePromoteScratchLine`.

One structural-typing subtlety worth flagging for Issue 10: `CategoryChip.tsx`'s `onDelete`/`onEdit` props are typed against its own local `CategoryChipCategory` (name/color/system/remaining/completed — no `_id`/`id`), not the full `Category`. `App.tsx`'s `handleDelete(category: Category)` and `setEditingCategory` (typed `Category | null`) both get passed straight through as those callbacks with no cast — this works because `CategoryChipCategory`'s fields are a subset of `Category`'s, so a `CategoryChipCategory` argument structurally satisfies `Category`'s required fields (`name`/`color`) with everything else optional. Confirmed this compiles cleanly rather than assuming it; no `as Category` cast was needed anywhere in `App.tsx`.

**`App.test.tsx` fetch-mock typing (the one file needing real design work, not just mechanical conversion):** the original `App.test.jsx` did `vi.stubGlobal('fetch', vi.fn(...))` and then read assertions back off the *global* `fetch` binding (`fetch.mock.calls...`). Under `strict: true` this doesn't type-check — the ambient `fetch` global is typed as the real DOM `fetch` signature (`Promise<Response>`), which has no `.mock` property. Introduced a small `FetchMock` type alias (`Mock<(url: string, init?: FetchCallInit) => Promise<FakeResponse>>`, using vitest's exported `Mock<T>` generic) and a `stubFetch()` helper that stubs the global and *returns* the typed mock for the test to hold onto and assert against, instead of reading back through `fetch`. All ~13 tests were mechanically updated to use the returned `fetchMock` variable. `FakeResponse`/`FetchCallInit` are deliberately minimal stand-ins (`{ ok, status, json }` / `{ method?, headers?, body? }`) rather than the full DOM `Response`/`RequestInit` — matches exactly what `App.tsx`'s fetch calls actually send/read, and keeps `postCall[1].body` typed as `string | undefined` (matches `JSON.parse` cleanly) instead of the real `RequestInit.body`'s much wider `BodyInit | null`. `let todosData/categoriesData/searchData` were given explicit `: Todo[]`/`: Category[]` declarations up front, which was enough for every per-test object-literal reassignment (e.g. `priority: 'Medium'`) to get contextually typed against the union field and stay narrow — no per-object `satisfies`/annotations needed, unlike some of Issue 07's component test fixtures which weren't assigned into a pre-typed variable.
